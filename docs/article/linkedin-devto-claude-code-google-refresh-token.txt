Debugging Claude Code and Google MCP Quirks

Claude Code asks for a refresh token the MCP way, with the offline_access scope; Google issues refresh tokens only through access_type=offline. A step by step check of both sides, and the alternatives, from signing in hourly to scripting the token yourself.

What is in it:

- ⚠️ Claude Code stores no refresh token for the Workspace servers, so each sign-in ends with its one-hour access token.
- ❌ Google lists offline_access nowhere and rejects it with invalid_scope; its own access_type=offline works, but standard MCP clients do not send it.
- 🟢 Antigravity CLI sends access_type=offline and renews without a browser. Codex CLI behaves like Claude Code.
- ❌ Antigravity asks for full mailbox access (https://mail.google.com/) and keeps the refresh token in a mode 644 file next to the client secret.
- ❌ Every client on one OAuth client shares one grant: revoking one Codex token signed Antigravity out too.
